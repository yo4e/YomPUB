# YomPUB Core 0.1.0-draft.1

**Normative proposal · experimental · 2026-10-20.** Manuscript identifier: `yompub: 0.1-draft.1`.

This draft supersedes conflicting syntax suggestions in DESIGN_DRAFT.md for this prototype only. Breaking changes are expected before 1.0. MUST, MUST NOT and MAY express requirements of this draft. Implementation limits are reported separately from invalid syntax. Examples are informative unless identified as conformance fixtures.

## 1. Source and scope

For whitespace tests in this draft, “whitespace” means U+0009–000D, U+0020, U+00A0, U+1680, U+2000–200A, U+2028–2029, U+202F, U+205F, U+3000 and U+FEFF. Explicit ASCII trimming rules take precedence.

A publication is a directory containing one `book.md` and its referenced local images. Reading order is the source order of this single manuscript. ZIP, multiple content files, remote images, arbitrary HTML/CSS/JS, fixed layout, audio/video and publication-specific extensions are outside Core.

A processor MUST decode valid UTF-8, rejecting malformed byte sequences rather than replacing them. It MAY discard one initial UTF-8 BOM. CRLF and CR MUST normalize to LF before parsing. Source MUST contain Unicode scalar values; NUL, U+0001–0008, U+000B–000C, U+000E–001F and U+007F are invalid. TAB, LF and CR are allowed. Other Unicode characters, including combining sequences, joining controls, bidi controls and variation selectors, MUST be preserved in logical order. Do not normalize Unicode, reverse RTL strings or replace punctuation. Formatting syntax is not literal prose; CommonMark's escaping/entity rules still apply.

Source syntax validation and publication validation are distinct. A parser can produce a semantic document without file access. A publication validator MUST additionally verify every referenced image exists within the publication root and has the declared image format. It MUST NOT claim the complete publication is valid when assets are missing. Readers MUST report resource/decode failures; they MUST NOT silently delete content.

## 2. Header (not YAML)

The first line MUST be exactly `---`. A later line exactly `---` closes the header. The next line begins the CommonMark body; a blank separator is optional. The header consists only of `key: value` lines. Blank lines, comments and multiline values are invalid.

- A key matches `[a-z][a-z0-9-]*` and is case-sensitive.
- The colon is followed by one ASCII space; additional leading/trailing ASCII spaces and tabs in the value are stripped.
- Values MUST be nonempty after stripping and MUST NOT consist entirely of whitespace. They are plain literal Unicode strings. Quotes, `#`, `:`, braces and backslashes have no special meaning. There is no YAML typing, escaping, Markdown parsing or entity decoding in metadata.
- Duplicate keys (including unknown keys) are invalid.
- Unknown keys MUST produce a warning and have no Core semantic effect. They are not an extension mechanism. Source-preserving tools MUST keep their original source; Core AST export MAY omit them.

| Field | Requirement / meaning |
| --- | --- |
| `yompub` | Required. Exactly `0.1-draft.1`. Other values MUST be reported as unsupported version. |
| `title` | Required nonempty plain title. Independent of headings. |
| `author` | Optional single display string; absent means unknown, not an empty invented name. |
| `lang` | Required syntactically well-formed BCP 47 tag, case preserved. Use `und` for undetermined language. |
| `direction` | `ltr`, `rtl` or `auto`; absent means `ltr`. MUST NOT be inferred from language. |
| `writing-mode` | `horizontal-tb`, `vertical-rl`, `vertical-lr`; absent means `horizontal-tb`. No `auto`. |
| `cover` | Optional local image path as defined below. Explicit cover role, separate from body images. |
| `cover-alt` | Required iff `cover` exists, nonempty plain alternative description. |

BCP 47 well-formedness follows RFC 5646 §2.1 grammar (including grandfathered/private-use tags), prohibiting duplicate variants and duplicate extension singletons case-insensitively. Registry validity, canonicalization and preferred-value substitution are not required. Extensions/private use do not grant extra YomPUB behavior.

`direction: auto` uses first-strong direction according to HTML's `dir=auto` behavior for the rendered content element. Authors who know the direction SHOULD specify it. Writing mode controls block progression independently of inline direction. In particular Japanese `vertical-rl` ordinarily uses `direction: ltr`.

## 3. CommonMark profile and precedence

After the header, parse **CommonMark 0.31.2**, modified only by this specification. The inherited semantic vocabulary is:

- Paragraphs; ATX and setext headings; thematic breaks.
- Block quotes; ordered and bullet lists, including nesting, starts and tight/loose distinctions.
- Fenced and indented code blocks; code spans; emphasis and strong emphasis.
- Inline/reference links and images; autolinks; soft/hard line breaks.
- Backslash escapes and character references, with the extensions below.

Raw HTML blocks and inline HTML recognized by CommonMark MUST cause an error, not stripping, execution or fallback. Literal `<` that is not HTML remains text. Escaped/entity-encoded HTML-looking text and HTML inside code remain text. Link reference definitions resolve by CommonMark rules and are not visible blocks. Bare URLs are not automatically linked. Other Markdown extensions (footnotes, pipe tables, math, strikethrough, generic attributes, custom heading IDs, etc.) have **no special meaning** and retain whatever ordinary text/structure CommonMark assigns them.

Blocks are recognized before inlines, as in CommonMark. The two YomPUB inline constructs are recognized only at positions where the inline parser is looking for a token. They are not recognized inside code spans/blocks, raw HTML tokens, link/image destinations or titles, reference definitions, metadata or already-consumed extension fields. A backslash escape or entity that produces an opener yields literal text, not a new parsing pass. A malformed unescaped opener in ordinary inline text is an error.

Extension fields are **atomic plain text**, not recursively parsed Markdown. ASCII Markdown punctuation inside a ruby field is literal. For example `｜*海*《うみ》` has base `*海*`, not emphasis. Wrapping the whole ruby in `*...*` applies emphasis. Block syntax still wins: a line becoming a setext heading, for example, is parsed as a heading before inline content is considered.

CommonMark soft breaks MUST remain soft-break nodes, not forced line breaks or deleted characters. Web readers represent them as U+000A with CSS `white-space: normal`; platform segment-break transformation determines whether a space appears. Hard breaks are explicit semantic breaks. Do not insert spaces by concatenating/splitting CJK source manually.

## 4. Headings, chapters and TOC

A valid book MUST contain at least one nonempty top-level level-1 heading. The first heading MUST be level 1. A subsequent heading can increase by at most one level; any decrease is allowed. Headings inside lists or block quotes are invalid. Front matter prose before the first heading is allowed. Level 1 starts a chapter; levels 2–6 are subsections of the nearest preceding lower-level heading.

Assign every heading, regardless of level, a document-order ID `h-N`, where N is its 1-based decimal ordinal, no leading zero. IDs are derived, not authored. Repeated heading text has distinct IDs. No slugging, normalization, locale rules or hidden filename component is used.

The ordinary TOC MUST be derived from these headings in source order with their levels and IDs. It does not include the metadata title or cover. A plain TOC label concatenates inline text, base text of ruby, text-run values, code contents, image alt and recursively emphasized/linked children; every soft/hard break becomes one ASCII space. Ruby readings are not duplicated in the label. Structured renderers MAY preserve heading inline semantics in TOC labels as well.

Internal links target only `#h-N`. Every such target MUST exist. IDs change when headings are inserted earlier; this is an explicit draft tradeoff, not stable authored anchors.

## 5. Links and images

After CommonMark unescaping/entity decoding, link destinations MUST be one of:

- `#h-N` as above;
- an absolute HTTP(S) URL with a nonempty host and no username/password;
- a simple `mailto:local@domain` address, with nonempty local and domain parts and no additional `@`, query, headers or fragments.

Schemes are case-insensitive. Whitespace, ASCII control characters and backslashes are forbidden in destinations. URL percent escapes are ordinary URL data; processors MUST preserve the authored decoded destination string, not rewrite it to another URL. URL interpretation is delegated to the URL standard. Protocol-relative, file, data, javascript, relative document links and arbitrary schemes are invalid. Empty destinations are invalid. Readers MUST NOT fetch link targets automatically; normal user-initiated navigation is permitted.

Image sources and the cover path are local references, not URLs:

- One or more nonempty path components separated by `/`, relative to the publication directory.
- No component may be `.` or `..`. Leading slash, double slash and trailing slash are invalid.
- No backslash, `%`, `?`, `#`, `:`, whitespace, ASCII control or DEL anywhere.
- Final suffix MUST be `.png`, `.jpg`, `.jpeg` or `.webp`, case-insensitive.
- Other Unicode filename characters are allowed and preserved exactly. The same filename string identifies the same resource; no Unicode/case normalization is required.
- Resolution MUST stay inside the publication root, including filesystem link resolution. Implementations MAY reject symlinks entirely, but must disclose that limitation.
- Encoded path traversal is forbidden because `%` is forbidden, not decoded repeatedly.

The image file bytes MUST be of the named format; a renamed HTML/SVG file is not an image. A viewer must also report actual decode failure. PNG, JPEG and WebP are the draft's baseline image formats. SVG and animated media are deferred. Frame animation is not a required semantic effect of Core; authors must not rely on it.

Images inherit CommonMark's label syntax only for text, emphasis, strong, code and soft/hard breaks. Links, images, ruby and text runs anywhere inside alt are invalid, including under emphasis. Flatten supported label content by the TOC text rule. Empty alt explicitly denotes decoration; a cover requires nonempty alt. Preserve CommonMark image/link title strings separately from alt/label. Title is advisory text, not a figure caption.

## 6. Ruby

Syntax: `｜base《annotation》` using U+FF5C, U+300A, U+300B. One nonempty plain base is related to one nonempty plain annotation. Group ruby only; no per-character distribution, multiple readings, nesting or placement language.

Scan from an unescaped U+FF5C at an inline token position:

1. Read until the first unescaped `《` on the same source line. The base MUST NOT contain unescaped `｜` or `》`.
2. Read until the first unescaped `》` on that line. The annotation MUST NOT contain unescaped `｜` or `《`.
3. Decode fields as below. Neither may be entirely whitespace or contain a decoded CR/LF.
4. Emit a ruby node with `base` and `annotation`. Missing delimiters or empty fields are errors.

A backslash followed by any ASCII punctuation recognized by CommonMark, or by `｜`, `《`, `》`, escapes that character. Other backslashes remain literal. Escaped characters never act as delimiters. Recognized CommonMark character references are decoded once; decoded delimiters are plain content. Do not decode entities created by escaping an ampersand. No field whitespace trimming or Unicode normalization occurs.

Outside ruby, `\｜`, `\《`, `\》` also produce literal markers; an ordinary `《` or `》` does not begin an extension. Inside code these backslashes retain CommonMark code semantics. There is no implicit kanji detection or ASCII-bar ruby alias.

A renderer MUST preserve the base↔annotation relationship. An HTML renderer uses `ruby` and `rt` (optionally `rp` fallback) and MUST NOT flatten the reading into body text. The reading inherits language from the containing content; separate annotation language is outside this draft. Placement comes from the platform's ruby/writing-mode support.

## 7. Isolated language/direction text run

Syntax: `{{language|direction|text}}`, two ASCII opening braces, two separator bars, two closing braces.

- Language follows the header `lang` rules, without whitespace or field unescaping.
- Direction is exactly `ltr`, `rtl` or `auto`, without whitespace.
- Text is a nonempty plain field, scanned to the first unescaped `}}` on the same source line.
- Unescaped `|`, `{` or `}` inside text is invalid; escape them with a backslash or use entities. The same field escape/entity decoding as ruby applies.
- Text must not be entirely whitespace or contain decoded CR/LF. Preserve its other whitespace.
- The whole run is atomic; apparent ruby, emphasis, code or link notation in its text stays literal. It cannot contain another run.
- The whole run may be emphasized, or used inside a link label. It may not occur inside image alt.

Its semantics are local language plus isolated inline direction, separate from the surrounding paragraph. An HTML renderer uses `bdi lang="..." dir="..."`. Isolation MUST be maintained even when the local direction equals the parent direction; `auto` uses first-strong direction inside the isolated run. No bidi override or manual reversal is implied. Writing mode is inherited from the book.

For example, an Arabic paragraph may contain `{{en|ltr|A-12 (2026)}}`. The run's trailing punctuation cannot change the surrounding paragraph's bidi resolution as if it were an unisolated neutral sequence.

## 8. Semantic interchange model

The JSON projection below is normative for fixture comparisons. An implementation may use any internal representation if it preserves these semantics. Object-key order is irrelevant; array order is significant. Adjacent text nodes MUST coalesce; zero-length text nodes MUST be omitted. Strings preserve code points after the specified parsing operations.

Top-level object:

```
{
  format: "0.1-draft.1",
  metadata: {title, author: string|null, lang, direction, writingMode,
             cover: {src, alt}|null},
  blocks: Block[],
  toc: {id, level, label}[],
  assets: string[]
}
```

`assets` is the unique set of all image/cover paths, sorted lexicographically by UTF-16 code units (the JSON comparison convention; not locale collation). Derived TOC/assets carry no additional authored content. Unknown header fields and source positions are not in this Core projection; warnings remain separate.

Blocks:

| type | Other fields |
| --- | --- |
| `paragraph` | `children: Inline[]` |
| `heading` | `level: 1..6`, `id`, `children: Inline[]` |
| `blockquote`, `item` | `children: Block[]` |
| `list` | `ordered: boolean`, `start: integer` (1 for bullets), `tight: boolean`, `children: item[]` |
| `codeBlock` | `value`, `info` (decoded and trimmed CommonMark fence info, or empty for indented code) |
| `thematicBreak` | none |

Inlines:

| type | Other fields |
| --- | --- |
| `text`, `code` | `value` |
| `softBreak`, `hardBreak` | none |
| `emphasis`, `strong` | `children: Inline[]` |
| `link` | `href`, `title` (empty when absent), `children: Inline[]` |
| `image` | `src`, `alt`, `title` (empty when absent) |
| `ruby` | `base`, `annotation` |
| `span` | `lang`, `direction`, `value` |

The type declaration in `src/model.d.ts` is an implementation aid. The rules in this document take precedence. A JSON export is a semantic projection, not a byte-preserving source serializer.

## 9. Failure, support and rendering contract

Invalid input MUST produce an explicit diagnostic and MUST NOT be labeled a valid book or rendered with the erroneous semantics silently dropped. Unsupported versions/capabilities/resources MUST be distinguished from successful parsing. Implementations MAY retain the previous successfully loaded publication after failure. Unknown metadata warnings are nonfatal.

Readers MUST preserve all supported Core semantics. They MAY change typography, spacing, colors and text size without changing meaning. They MUST expose structure, language, direction, alt and ruby to their platform's accessible semantic representation, derive navigation, and allow reflow. No exact font, pixel geometry, page count or pagination is required. Vertical mode MUST not be implemented by rotating flattened strings.

The reference implementation limits source to 2 MiB, each image to 10 MiB, referenced images to 40 MiB total, folder inventory to 2000 files and parse nesting below 120 levels. These are disclosed implementation limits, not Core syntax. Exceeding one is a `LIMIT` diagnostic, not silent truncation. CLI rejects symlink assets. Image signature validation in CLI is not a full decode; the viewer decodes all referenced images before replacing the current book.

## 10. Conformance and open evaluation

Data-only examples in `tests/fixtures/conformance.json` specify source/body, expected inline/block projection or diagnostic code. The sample AST files capture full document semantics. A conforming implementation must satisfy the normative rules even for inputs not in these examples. This corpus is not an exhaustive proof of CommonMark conformance or global typography quality.

Still to evaluate: independent implementation, longer real books, native-speaker RTL review, screen readers, font-dependent Mongolian/Indic/Thai behavior, useful scope for footnotes/captions, stable authored links, block language changes and mixed-language ruby. These are evaluation tasks, not hidden defaults.

## Normative dependencies

- [CommonMark 0.31.2](https://spec.commonmark.org/0.31.2/), block/inline parsing and escapes.
- [RFC 5646](https://www.rfc-editor.org/rfc/rfc5646), language-tag syntax.
- [HTML directionality](https://html.spec.whatwg.org/multipage/dom.html#the-dir-attribute), `auto` direction and bidi isolation.
- [URL Standard](https://url.spec.whatwg.org/), HTTP(S) URL interpretation.
- [CSS Writing Modes Level 4](https://www.w3.org/TR/css-writing-modes-4/), horizontal/vertical reading intent.

Implementer guidance: [W3C inline bidi markup](https://www.w3.org/International/articles/inline-bidi-markup/). It informs the HTML mapping but does not add source syntax.
